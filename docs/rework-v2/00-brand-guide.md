## 00 / Introduction — How to Use This Guide

A practical source of truth for PASTI's visual, verbal, interface, and motion language.

This guide defines the working brand system for PASTI People. It is intended for designers, developers, motion designers, marketing teams, presentation designers, and external production partners.

### Operating Principle

The brand must feel capable before it feels decorative. Every visual and interaction decision should reinforce certainty, precision, momentum, practicality, or impact.

### Decision Hierarchy

1. Brand core and brand personality come first.
2. Readability and usability take priority over decoration.
3. Motion must serve reveal, focus, progress, transition, or response.
4. Digital expression may be bold, but it must remain controlled and enterprise-credible.
5. When in doubt, simplify rather than add another effect.

### Status Notes

- Slate Navy and Pure White are treated as core brand surfaces.
- Cobalt Blue and Cyan Spark are working digital accents for rework and interactive systems.
- PASTI Yellow is the signature brand accent; the exact production HEX must be sampled from the official master logo.
- The typography direction is approved as Super Editorial × Functional Precision; exact production font files remain a separate implementation decision.

## 04 / Voice — Tone of Voice

Confident, clear, direct, and outcome-led.

### Core Rules

- Confident, not arrogant.
- Clear, not simplistic.
- Direct, not cold.
- Outcome-led, not technology-led for its own sake.
- Use active voice and decisive verbs.

### Preferred Verbs

Build · Deliver · Scale · Engineer · Transform · Simplify · Accelerate · Integrate · Launch

### Avoid

- maybe / hopefully / we try
- empty claims of innovation
- synergy / paradigm shift
- cutting-edge with no evidence
- needless technical jargon

### Example

**Avoid**: "We hope to help businesses innovate with cutting-edge solutions."
**Prefer**: "We build systems designed to perform, scale, and move the business forward."

## 05 / Color — Color System

A navy-led precision brand with digital blue accents and a distinctive yellow signal.

| Color | Value | Primary Role |
|---|---|---|
| Slate Navy | `#0F172A` | Primary dark environment |
| Pure White | `#FFFFFF` | Primary light / contrast surface |
| Surface Neutral | `#F8FAFC` | Editorial light surface |
| Cobalt Blue | `#2563EB` | Core digital accent / interaction |
| Cyan Spark | `#06B6D4` | Secondary highlight / technical cue |
| PASTI Yellow | Exact HEX pending master logo | Signature brand accent / signal |

### Color Hierarchy

- Slate Navy is the primary digital environment and authority color.
- Pure White and Surface Neutral create contrast and strategic visual resets.
- Cobalt Blue is the core digital interaction accent.
- Cyan Spark is a secondary technical highlight; it should remain restrained.
- PASTI Yellow is the signature brand signal and should remain scarce enough to feel meaningful.

### Critical Contrast Rule

Cyan Spark (`#06B6D4`) must not be used as readable text directly on Pure White (`#FFFFFF`) without sufficient dark containment or contrast treatment.

### Recommended Digital Ratio

| Color Family | Recommended Presence |
|---|---|
| Slate Navy / dark tones | 55–65% |
| White / Surface Neutral | 15–20% |
| Cobalt / supporting blue | 10–15% |
| Cyan Spark | 3–5% |
| PASTI Yellow | 1–3% |

> **[Homepage Execution Note]** This brand-level ratio permits PASTI Yellow a small but real presence (1–3%). For the current homepage rework, the section-by-section art-direction locks (see `04-homepage-spec.md`) have collectively landed on a stricter posture: **Yellow is off by default in nearly every section** (Selected Work, Platforms, PAQ/FAQ, and Footer all explicitly locked "no Yellow unless a genuinely meaningful, explicitly justified moment appears"). This is a homepage-execution-level tightening, not a brand-level change — the 1–3% ratio above remains the brand's own working guidance and is not overridden by it. If a future section or campaign wants to use Yellow more liberally within this brand ratio, that is a legitimate brand-level allowance and should be evaluated on its own merits rather than treated as a violation.

## 06 / Typography — Typography System

**Super Editorial × Functional Precision.**

### Display Direction

Display typography is a primary visual device. It should be oversized, tightly led, confident, and compositionally intentional.

- Grotesk / neutral editorial character
- High legibility
- Tight line-height
- Negative tracking
- Asymmetric placement
- Occasional crop or viewport-edge bleed

### Avoid

- Sci-fi typefaces
- Decorative futuristic fonts
- Rounded SaaS typography
- AI-slop display fonts
- Mono as the primary voice

### Scale

| Role | Size | Line Height | Tracking |
|---|---|---|---|
| Hero / Display XL | `clamp(72px, 9vw, 160px)` | 0.88–0.98 | -0.02em to -0.05em |
| H1 / Section Monumental | 56–96px | 0.95–1.05 | -0.02em to -0.04em |
| H2 | 36–56px | 1.00–1.10 | -0.01em to -0.03em |
| Body Large | 18–24px | 1.4–1.6 | 0 |
| Body | 16–18px | 1.5–1.7 | 0 |
| Metadata | 11–14px | 1.2–1.4 | 0.04em–0.08em |

## 07 / Layout — Grid & Spacing

Structured rhythm with enough flexibility for editorial composition.

### Base Grid

**8px.** Allowed increments: 4 / 8 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96 / 128 / 160. Use 4px only for micro-spacing.

### Responsive Gutters

| Tier | Container | Outer Gutter |
|---|---|---|
| Desktop | 1280–1440px container | 48–80px outer gutter |
| Tablet | Fluid | 32–48px |
| Mobile | Fluid | 20–24px |

### Section Rhythm

- Desktop: 120–200px vertical spacing depending on composition.
- Tablet: 96–144px.
- Mobile: 72–112px.
- Pinned scenes may use viewport-based heights instead of fixed section spacing.

## 08 / Graphic Language — Visual Language

A small number of repeatable devices should make PASTI recognizable without the logo.

**01 — Precision Framing**
Frames, edge lines, crops, and alignment markers used to structure information.

**02 — Signal**
A recurring active line, point, route, or progress element that communicates state and motion.

**03 — Editorial Crop**
Images and UI are often shown as oversized details, cropped windows, partial interfaces, or masks rather than browser mockups.

**04 — Large Type as Graphic**
Typography may become a structural visual element rather than simply a heading.

### Rule

Graphic devices must never become fake HUD decoration. If a line, node, frame, or vector does not support hierarchy, state, progression, or transition, remove it.

## 10 / Interface — UI Direction

Structured, content-led, minimal, and expressive only where the content benefits.

### Buttons

- Compact and precise rather than oversized pill buttons.
- Primary radius: 6–8px.
- Secondary actions may be text-led or outlined.
- Hover should use line travel, arrow shift, color state, or signal movement rather than exaggerated scaling.

### Cards

- Cards are a grouping tool, not the default layout for every section.
- Recommended radius: 8–12px.
- Prefer tonal separation, borders, or masks over heavy shadows.
- Avoid large identical rounded rectangles repeated across the page.

### Borders & Surfaces

- 1px structural borders.
- Low-opacity white/slate in dark environments.
- Subtle navy/neutral on light surfaces.
- Use light surfaces as deliberate resets, not the default canvas.

> **Note for Design Tokens reconciliation**: the existing `06-design-tokens.json` radius scale (`sm: 6px`, `md: 10px`, `lg: 20px`) does not map 1:1 onto this brand-level button/card radius guidance (buttons 6–8px, cards 8–12px). This is flagged for reconciliation at the Design Tokens layer — per the consolidation conflict-resolution principle, the token must be corrected to conform to the Brand Guide, not the other way around. See `05-changelog.md` for tracking.

## 11 / Motion — Motion Identity

**Controlled Momentum.**

PASTI motion should feel precise, smooth, weighted, responsive, and intentional. Motion is not decoration; it is a system for reveal, focus, progress, transition, and response.

### Motion Functions

Reveal · Focus · Progress · Transition · Response

### Intensity Hierarchy

| Intensity | Sections |
|---|---|
| Heavy Signature | Hero · What We Build · Selected Work · Platforms |
| Medium | Testimoni · Insight |
| Quiet | Trusted by Brand · FAQ · Footer |

### Timing

| Tier | Duration | Use |
|---|---|---|
| Micro | 120–250ms | Hover / focus / underline / arrow |
| Standard | 300–600ms | Cards / masks / simple state changes |
| Cinematic | 800–1600ms | Major reveal / section takeover / narrative transitions |

### Easing

Primary CSS: `cubic-bezier(0.16, 1, 0.3, 1)`. GSAP: `power3.out`, `power4.out`, `expo.out`. Avoid bounce, elastic, and cartoon spring behavior.

## 12 / Motion Tech — Motion Technology

A production stack that supports high-end motion without sacrificing control.

### Mandatory

- **Lenis** — smooth scrolling
- **GSAP** — timeline and interaction engine
- **GSAP ScrollTrigger** — scroll-driven choreography

### Optional

- **SVG/vector motion** — progress, masks, paths, state
- **WebGL / Three.js** — only when 3D materially improves content

### WebGL Rule

Do not add 3D simply to make the site look "advanced." Approved usage should support product/media storytelling, especially Selected Work or Platforms.

### Vector Rule

Vector animation should communicate progress, signal, transition, mask, index, path reveal, or state. Avoid decorative random motion.

## 13 / Responsive — Responsive Behavior

**Recompose rather than scale.**

| Tier | Principle | Behavior |
|---|---|---|
| Desktop | Full experience | Full cinematic choreography, largest typography, richer depth and scroll interactions. |
| Tablet | Reduced detail | Shorter pin durations, fewer secondary graphics, reduced parallax. |
| Mobile | Recomposed | Simplified scroll choreography, reduced WebGL, large type retained, no long scroll traps. |

### Reduced Motion

Honor `prefers-reduced-motion: reduce`. Disable decorative idle animation, long pins where appropriate, heavy parallax, and non-essential 3D while preserving a strong static composition and full content accessibility.

## 14 / Anti-Template — Anti AI-Slop & Anti-Template Rules

The website should look authored, not generated.

- No purple-blue gradient blobs.
- No random neon orbs.
- No giant glass cards.
- No generic floating dashboard collage.
- No random 3D chrome spheres.
- No meaningless particle fields.
- No fake futuristic HUD.
- No pill UI everywhere.
- No oversized border radius as a default language.
- No meaningless glow.
- No generic startup layout.
- No identical three-card grid as a default section pattern.
- No fade-up animation everywhere.

### Preferred Alternative

Asymmetry, editorial scale, strong crop, real proof, controlled motion, precise spacing, dark/light rhythm, and a small number of repeatable brand devices.

## 15 / Website Philosophy — Digital Experience Philosophy

Balance proof, expression, and brand.

| Share | Layer | Includes |
|---|---|---|
| 50% | Proof | Projects · systems · outputs · real capability |
| 30% | Expression | Typography · motion · composition · image treatment |
| 20% | Brand | Color · signal · voice · graphic system |

**Goal**: PASTI should look like a serious technology company with exceptional digital taste — not a design studio that happens to code, and not a software vendor with no creative character.

### Interaction Principle

Nothing moves without intent. Every movement must reveal, focus, communicate progress, transition between states, or respond to user input.

## 16 / Quality Control — Brand Quality Tests

Use these checks before approving any major design or implementation.

| Test | Question |
|---|---|
| Static Test | If motion is paused, does the composition still look premium? |
| Motion Test | Does animation improve hierarchy rather than distract from it? |
| Brand Test | If the logo is removed, does the page still feel like the same visual universe? |
| Enterprise Test | Would a CTO, enterprise buyer, or serious client still trust the brand? |
| Creative Test | Would a designer or creative stakeholder still perceive strong taste and craft? |

### Release Rule

A visually impressive effect does not justify release if it weakens readability, performance, accessibility, or enterprise credibility.

## 17 / Do & Don't — Execution Rules

Fast reference for production teams.

| Rule | Guideline |
|---|---|
| DO | Use real proof, projects, systems, and outcomes. |
| DO | Use typography at confident editorial scale. |
| DO | Use asymmetry, strong crop, and deliberate negative space. |
| DO | Use dark/light rhythm rather than one flat page tone. |
| DO | Use Cobalt/Cyan as restrained digital accents. |
| DO | Use PASTI Yellow as a scarce signature signal. |
| DO | Use motion with an explicit purpose. |
| DON'T | Copy Cuberto or another agency's visual grammar. |

| DON'T | Add random WebGL, glow, blobs, or particles. |
| DON'T | Use stock imagery clichés. |
| DON'T | Over-animate quiet content sections. |
| DON'T | Use Cyan text directly on pure white without sufficient contrast. |
| DON'T | Let motion interrupt content comprehension. |

- [ ] PASTI Yellow is used sparingly as a signature signal.

- [ ] 8px spacing discipline is maintained.
- [ ] Cards are used only where structurally useful.
- [ ] Motion hierarchy is respected; not every section is heavy.

- [ ] Reduced-motion mode preserves composition and content access.
- [ ] No AI-slop / generic SaaS visual patterns are present.
- [ ] Static screenshot quality is strong before motion is considered.
- [ ] Real proof replaces generic decorative content wherever possible.
